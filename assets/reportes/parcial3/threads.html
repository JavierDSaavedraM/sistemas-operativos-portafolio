Global Interpreter Lock — por qué Python no es verdaderamente paralelo

Python tiene un GIL: un mutex que solo permite que un thread ejecute bytecode a la vez, incluso con muchos cores disponibles. C no tiene ningún equivalente — cada thread obtiene su propio core.

Cómo el OS asigna tiempo de CPU a cada thread

El scheduler del OS reparte quantums entre threads. En Python, el GIL fuerza round-robin estricto (1 thread a la vez). En C, el OS puede asignar hasta N threads simultáneamente — uno por core disponible.

Python puro vs Python con wrapper a C

Cuando Python llama código C via ctypes, Cython o cffi, el GIL puede liberarse con Py_BEGIN_ALLOW_THREADS. Mientras la extensión C corre, todos los threads disponibles pueden usar sus propios cores.
